Summary

One sentence. Capability and price-performance are improving fast, but the benchmarks are noisy, entry-level hiring is tightening, and the winners are people who can show measured reliability, cost and safety on real systems.

1
Cheap models are good enough for most calls. Small-tier input prices are $0.10 to $0.30 per million tokens, flagships have flattened at $10 / $50, and caching and batch discounts (cache reads at 5 to 10% of input, batch 50% off) often matter more than model choice. Google is raising some prices on Dec 1 and Jan 1, so "prices only fall" no longer holds for every vendor.
2
Benchmarks are unreliable. SWE-bench Verified is reported as contaminated, SWE-bench Pro grading is questioned, OSWorld results differ by source, and METR says its suite is unreliable above 16 hours and its page is no longer actively updated. Your own small eval set is the trustworthy instrument.
3
Open models trail by about 4 months, or about 12 index points, but the best ones are 300B to 2.8T parameter mixture-of-experts models. On one rented GPU you run a dense model near 27B. Use open models for serving, fine-tuning and cost labs rather than as frontier substitutes.
4
Software hiring recovered at the senior end. Indeed shows postings about 15% above Feb 2025 but 27.5% below pre-pandemic, 71% of the rebound from senior roles, and entry-level only 4.5% of software postings. Stanford finds 22 to 25 year olds in exposed jobs 19% below peers.
5
The AI-skill pay premium is smaller than the headlines. PwC says 62% and Lightcast says 28%, but those compare different roles. Indeed's within-occupation estimate is about 5%.
6
Agent reliability comes from structure, not from more agents. Anthropic, Cursor and Cognition independently report that unverified "done" claims and parallel writers cause failures. What works: one feature per session, git checkpoints, a clean-context reviewer, and end-to-end tests the agent cannot edit.
7
Security failures share one root cause: trust granted by location or name instead of content (Cursor MCPoison, Codex CLI config, malicious skills). The architectural fix is to avoid combining private data, untrusted input and outward action in one agent.
8
Serving engineering is concrete and learnable. Learn vLLM first, then SGLang. Report TTFT and TPOT percentiles and goodput at a stated SLO, and expect "up to Nx" vendor claims to shrink under honest workloads. A credible student project costs under about $10 on a rented 24 GB GPU.
9
Regulation slipped but did not vanish. EU high-risk obligations moved to Dec 2027 and Aug 2028. User-disclosure duties and general-purpose-model enforcement are already live.
10
Most adoption statistics are weak evidence. Gartner's 40% cancellation forecast rests on a 3,412-person webinar poll, and the MIT "95% fail" figure has a small, contested sample.
What changed from version 1.
  • EU AI Act: v1 said fully applicable from Aug 2026. The Digital Omnibus (in force 27 Jul 2026) delays high-risk rules to Dec 2027 and Aug 2028.
  • Pay: v1 implied a large AI premium. Within-occupation evidence says about 5%.
  • METR: v1 cited a 3 to 7 month doubling range. METR's own page states no doubling time and is no longer actively updated, so I removed that forecast.
  • Claude Code "22 advisories": I could not confirm this from the OWASP report itself, so I no longer use it. I cite verified incidents instead.
  • Token prices: v1 treated them as falling everywhere. Google has scheduled increases.
  • Gartner: v1 stated "cancelled." Coverage is inconsistent between "cancelled" and "paused, restructured or cancelled", and I could not read the press release. I now flag it.

Worked example (my arithmetic). An agent runs 20 turns, adding 2,000 tokens a turn and resending everything. Billed input is 2,000 x (1+2+...+20) = 420,000 tokens. On Sonnet 5.5 at $2 per million that is $0.84 with no caching. With caching, the 40,000 new tokens are written at 1.25x ($2.50 per million, $0.10) and the other 380,000 are read at $0.10 per million ($0.038), about $0.14 in total. That is about 6x cheaper, before output tokens. It only works if the prefix stays byte-identical, which is why deterministic tool ordering matters (the 2026-07-28 MCP spec requires it for cache hits).

  • Price decline by capability level. Epoch estimates matching a fixed capability got about 40x cheaper per year, ranging from 9x to 900x by milestone. A separate workshop paper says 5 to 10x. Both are secondary here. Goldman's 60 to 70% yearly decline per token is a different, more conservative measure.
  • Capex. Hyperscaler 2026 guidance sums to about $700 to $725B (Meta $125 to $145B, Alphabet $180 to $190B, Microsoft about $190B, Amazon about $200B), partly attributed to chip and memory price inflation. Secondary, from April earnings.
  • Lab revenue. Run rates are reported but not comparable (gross versus net booking). I do not use them.

Evaluation and observability: the consensus

  • Start with 20 to 50 tasks drawn from real failures. Grade outcomes, not paths. Use code graders first and calibrate any model grader against humans. Read transcripts regularly. (Anthropic, Jan 2026, primary.)
  • Report pass^k beside pass@k: at 75% per trial, passing 3 of 3 happens about 42% of the time.
  • Error analysis: open-code at least 100 traces, noting the first failure in each, then count failures by category until new modes stop appearing. (Hamel Husain, sec.)
  • A vendor-run survey of about 1,300 respondents finds 89% have observability but only 52% run offline evals and 37% online evals, and 57% have agents in production. Treat as directional.
  • OpenTelemetry GenAI conventions are the shared trace format. I could not confirm their stability status.

Frameworks

Anthropic's guidance is to start with direct API calls and understand any framework underneath. Agent-specific serving

  • Continuum: pins KV for a time-to-live while a request waits on a tool call, with program-level first-come scheduling. Over 8x better average job completion time on SWE-Bench, BFCL and OpenHands. Hardware not stated.
  • TOPAS: workflow-aware prefix scheduling in SGLang. Up to 39.8% lower mean completion time on synthetic DAGs, 9.8% and 22.0% on two MetaGPT workflows.
  • The recurring problems are long shared prefixes, cache eviction during tool pauses, and scheduling at the program rather than request level. Benchmarks that disable prefix caching do not measure this.

Kernels

FlashAttention-3 reports 1.5 to 2.0x over FA2 on H100 (up to 740 TFLOPs/s FP16). FlashAttention-4, written in CuTe DSL, reports up to 1.3x over cuDNN and 2.7x over Triton on B200 (secondary). In a few weeks a student can realistically write a Triton fused softmax or simple attention kernel and read FA3 and FA4 for the ideas. Rewriting FA4 is not realistic.

Benchmarking honestly

  1. Report TTFT and TPOT at p50 and p99, not means.
  2. Report goodput under a stated SLO (for example over 90% of requests within the TTFT and TPOT limits).
  3. Plot throughput against tokens per second per user, not a single point.
  4. Use realistic input and output lengths. Turn prefix caching on or off on purpose, and use a shared-prefix agent-style workload.
  5. Check accuracy after quantization.
  6. Pin engine version, hardware and precision, and compute cost per million tokens from the hourly price.

InferenceX (SemiAnalysis, open source, Apache 2.0) and MLPerf Inference v6.0 (April 2026) are the public references. The MLPerf figures here come from secondary summaries.

Defenses and how well they work

  • Lethal trifecta (Willison, Jun 2025): private data, untrusted content and external communication. The only safe option is not to combine all three. primary
  • Meta's Rule of Two (Oct 2025): in one session, at most two of untrusted input, sensitive access, and state change or outward communication; all three requires human supervision. It supplements least privilege. primary
  • CaMeL (arXiv 2503.18813): a design-level defense using a planning model and a quarantined model with provenance tracking. It solves 77% of AgentDojo tasks with provable security versus 84% undefended, about 7 points of cost. primary
  • Adaptive attacks (arXiv 2510.09023): 12 published defenses were bypassed with attack success above 90% for most, though most had reported near zero. primary
  • Claude Code permissions: tiered approvals with allow, ask and deny rules, managed policies and a classifier-based auto mode. Codex's model was not read. primary
  • Model-level attack success rates from vendor system cards are reported in secondary sources and are not comparable across setups. I do not rely on them.

6. The thinking underneath

Eight ideas appear across all five streams. They explain why the workflows below look the way they do.

Verification is the bottleneck.

Writing is cheap, checking is not. Every successful harness (Anthropic's feature list, Cognition's reviewer, Cursor's judge) adds an independent check. Commits rose 180 to 240% in the NBER study while releases rose about 30%.

Reliability compounds.

At 95% per step over 10 steps, success is 60%. At 90% it is 35%. (My arithmetic; Anthropic's pass^k example is 0.75 cubed, about 42%.) So reduce steps, add checkpoints and verify each stage.

Context is a budget.

Compaction, clearing, notes and sub-agents all exist to keep the smallest set of high-signal tokens in view.

Cost per task, not per token.

Agents use about 4x chat tokens and multi-agent about 15x. A task that costs $0.14 cached and $0.84 uncached is a design choice, not a pricing accident.

Prefix stability is an economic asset.

Caching, deterministic tool ordering, prefix-reuse engines and cache-aware routing are one idea at four layers.

Measure honestly.

Benchmarks leak and saturate, vendor numbers are "up to." Build a small private eval, fix the workload, report percentiles and variance.

Trust content, not location.

Names, paths and registries are not security boundaries. Treat configs, skills and MCP servers as code.

Limit authority by design.

Assume injection will succeed. Remove a trifecta leg, scope credentials and add a human gate for irreversible actions.

7. The exact workflows

Each runbook is built from the evidence above. Where a number is my suggestion rather than a sourced figure, it says so.

W1. Agentic coding session (daily driver)

Spec in a file→Feature list JSON, all failing→One feature per session→E2E test the agent cannot edit→Commit→Clean-context review→You merge
  1. Start each session by reading the git log and the progress file. End by committing and updating the progress file.
  2. Writes stay single-threaded. Use parallel agents for reading, research and review, not for competing edits.
  3. Never accept "done" from unit tests or a curl alone. Require an end-to-end check.
  4. The reviewer sees only the diff and the spec.
  5. Archive session files. CS2680 requires them with every assignment.

W2. Evaluation loop

Collect 20 to 50 real failures→Tasks with reference solutions→Code graders first→Run k trials, report pass@k and pass^k→Read transcripts→Error-analysis taxonomy→Add new failures as tests
  1. Isolate trials in clean environments so runs do not contaminate each other.
  2. Grade outcomes, not the path the agent took.
  3. If you use a model grader, compare it with your own labels on a sample before trusting it.
  4. Review at least 100 traces in total (suggested by Husain) and stop when no new failure mode appears.

W3. Cost and latency reduction (Assignment 3 style)

Fix workload and success check→Trace tokens and dollars per step→Stabilize the prefix and cache it→Route easy calls to a small model→Batch offline work (50% off)→Summarize sub-agent output→Re-measure with variance
  1. Success rate must stay fixed. Report cost and latency per completed task, with run-to-run variance.
  2. Keep tool lists and system prompts byte-identical between calls, and order tools deterministically.
  3. Sub-agents return 1 to 2k token summaries, not raw transcripts.
  4. Overlap independent tool calls instead of running them in sequence.
  5. Change one thing at a time and keep a table of before and after.

W4. Serving and profiling (Assignments 4 and 5 style)

Hypothesis with a number→Baseline on vLLM→Measure TTFT, TPOT p50/p99, goodput→Toggle prefix cache, chunked prefill→Quantize and re-check accuracy→Repeat on SGLang→Cost per million tokens
  1. Rent a 24 GB GPU (about $0.34 to $0.44 an hour community pricing, so a 20-hour project is roughly $7 to $9). Stop the instance when you finish.
  2. Use an 8B-class model at FP8 or BF16. I did not source the 24 GB fit, so confirm memory before you start.
  3. Use a shared-prefix, multi-turn workload so you actually test prefix reuse.
  4. Write the hypothesis before changing anything, then record what moved.

W5. Agent security review

List data, inputs, actions→Score the trifecta→Remove one leg or gate it→Least-privilege credentials→Pin and vet dependencies, skills, MCP servers→Log every tool call→Red-team with injected content
  1. Treat repo config files, MCP configs and skills as executable code. Review content, not names.
  2. Use hard enforcement (permissions, sandboxes, separate dev and prod), not prompt instructions.
  3. Do not rely on an injection filter. Published defenses were bypassed above 90% by adaptive attacks.
