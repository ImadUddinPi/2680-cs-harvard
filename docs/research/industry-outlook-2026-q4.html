Industry Outlook Q4 2026

Where AI is heading, what is in demand, the workflows that earn money, and what the next two to three months likely look like. Written for someone starting CS2680 and planning an AI career.

Thesis. Producing code, text and plans is now cheap and getting cheaper. The scarce skill is making autonomous systems reliable, verifiable, affordable and safe. Every durable role in the data below sits on one of those four words.

For you. CS2680 is aimed at the right target. Its five assignments map to four in-demand abilities: directing agents (A1), building and evaluating them (A2), cost and latency engineering (A3, A5), and serving open models (A4). Two things the market is asking for are thin in the course: security architecture and production evaluation. I recommend adding both early (section 7).

4. The workflows, and the thinking behind them

Three workflows recur across the sources. The same mindset sits under all three.

A. Agentic engineering: how people ship software with agents

Write spec→Split into small tasks→Fresh agent per task in its own worktree→Tests first, run gates→Independent reviewer agent→Human merges
  • The spec is the main artifact. Code is an output you can regenerate.
  • Parallel workers get isolated copies of the repo. Sources suggest sub-agents for tasks of about 15 minutes and 3 to 5 teammates in agent-team modes.
  • A reviewer with its own context beats an agent reviewing itself. One source reports about 75% useful suggestions from a multi-agent review versus under 50% for single-agent review. Treat that figure as anecdotal.
  • Counterweight: one cited study found 89% of firms reporting no productivity change from AI. Measure results instead of assuming gains.
Thinking. Writing is cheap, so the bottleneck is verification. Invest in specs, tests and review instead of typing speed.

B. Building a production agent: the improvement loop

Define task and success check→Minimal loop and tools→Trace every step→Turn failures into eval cases→Cut tokens, calls, model size→Harden permissions
  • Start simple. Anthropic's guidance is to use the simplest thing that works and add structure after observed failures.
  • Manage context as a budget: compact near the limit (recall first, precision second), clear stale tool results, keep progress in a notes file, send exploration to sub-agents that return about 1,000 to 2,000 tokens, load data just in time.
  • Record each model call, tool call and retrieval as a span in one trace. OpenTelemetry conventions make traces portable. Eval suites are the part that locks you into a vendor.
  • Track cost per completed task, not per token. Token prices fall, but usage grows faster, so bills still rise.
Thinking. Treat the agent as a system under test. Every failure is a test case you have not written yet.

C. Serving and optimizing inference

Write hypothesis with a number→Profile: time, tokens, bytes→Change one layer→Re-run same workload→Keep what moved the metric
  • Decode is memory-bound, so the levers are fewer bytes (quantization, FP4), fewer passes (speculative decoding), reuse (prefix caching) and better packing (continuous batching, paged KV).
  • Prefill/decode disaggregation is now supported by the main engines. Setups differ per engine and misconfiguration can fail silently, for example a router that never transfers KV.
  • Agent workloads reuse long prefixes, which is why scheduling and prefix caching are in the course syllabus.
Thinking. Performance work is empirical. Predict, measure, attribute. It is the same loop as A5 in the course.

D. Securing agents: design so one injection cannot hurt you

List what the agent can read, see and send→Check the trifecta→Remove one leg or add a human gate→Least-privilege tools→Log and audit
  • The lethal trifecta is private data, untrusted content and external communication in one agent. The "Rule of Two" says an unsupervised agent should have at most two.
  • OWASP's 2026 report maps prompt injection to six of its ten agentic risk categories and lists real CVEs in coding agents, including allowlist and sandbox flaws, plus malicious MCP servers and package compromises.
  • Auto-approval allowlists and sandboxes that the agent's own output can modify deserve scrutiny. This is my inference from the cited CVEs.
Thinking. You cannot make the model immune. Limit the damage by architecture.

5. Underlying thinking, in four rules

  • Verification is the bottleneck. If you cannot check the output cheaply, you cannot scale the agent.
  • Context is a budget. More tokens is not better. The smallest set of high-signal tokens wins.
  • Measure outcomes at the task level. Cost, latency and success per task, with variance, on a fixed workload.
  • Least authority. Assume injection will happen, then cap what it can touch.

7. What to do with this

The data favors people who can show measured results on the four scarce abilities. A 12-week plan, aligned with CS2680, which gives you something to publish every three to four weeks:

  • Weeks 1 to 3 (M00 to M01). Finish the lesson plan. Add one item: a trace viewer. Assignment A1 is a web UI that streams agent trajectories, which is the same idea as observability.
  • Weeks 4 to 6 (A2 style). Build your agent loop with tracing from day one, and an eval set of 20 tasks that grows from failures. Publish the eval set and the failure analysis.
  • Weeks 7 to 9 (A3 style). Cost study: same success rate, lower dollars and latency. Show a before and after table with variance. Blog post.
  • Weeks 10 to 12 (A4 and A5 style). Serve an open 7 to 8B model on a rented GPU, measure quality loss against an API model, then profile and test one hypothesis per layer. Blog post.

Proposed changes to our curriculum (I will not apply these until you approve)

  • Add a security lab to M02. A trifecta checklist applied to your own agent, plus an injection test against it. It costs about two hours and addresses the scarcest skill.
  • Add production evaluation to M05. Build the trace-to-test-case loop, not just a benchmark runner.
  • Add context engineering to M02 and M04. Compaction and note files, using Anthropic's guide above as the reading.
  • Keep framework study light. Frameworks change monthly. Skills that transfer are the loop, schemas, traces and evals.
  • Keep the course's serving modules as they are. They are the least commoditized part of the market.
